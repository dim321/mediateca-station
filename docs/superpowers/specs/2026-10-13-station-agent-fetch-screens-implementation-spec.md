# Задание для coding agent: `fetch_screens` в репозитории станции

## Назначение документа

Передайте этот документ coding agent, запущенному в репозитории
`mediateca-station`. Агент должен сначала изучить текущую архитектуру,
существующий polling команд, HTTP-клиент, локальную идемпотентность и стиль
тестов, затем встроить функциональность в найденные границы. Не создавайте
параллельную систему команд и не меняйте Broadcast Hub из этого задания.

## Цель

Реализовать станционную команду `fetch_screens`. По команде процесс читает
активные DHCP-аренды телевизоров из `/var/lib/misc/dnsmasq.leases`, формирует
пары MAC/IP и отправляет их в существующий endpoint результатов Hub.

## Контракт входящей команды

Команда приходит в ответе `GET /api/agent/v1/commands`:

```json
{
  "commands": [
    {
      "id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "screen_id": null,
      "type": "fetch_screens",
      "params": {},
      "issued_at": "2026-10-13T14:00:00Z"
    }
  ]
}
```

Это команда станции:

- `screen_id` обязан быть `null`;
- `params` не содержит параметров;
- экранные операции, ADB и VLC для неё не запускаются;
- неизвестные типы команд продолжают обрабатываться по текущим правилам
  агента.

## Источник данных

Файл: `/var/lib/misc/dnsmasq.leases`.

Стандартная строка dnsmasq разделена пробельными символами:

```text
<expires> <mac_address> <ip_address> <hostname> <client_id>
```

Пример:

```text
1791903600 aa:bb:cc:dd:ee:ff 192.168.1.10 living-room-tv *
```

Правила:

1. Игнорировать пустые строки.
2. `expires` — Unix timestamp; `0` означает бессрочную аренду.
3. Включать только бессрочные или неистёкшие на момент чтения аренды.
4. Принимать только шестибайтовый MAC и IPv4 host-адрес.
5. Канонизировать MAC в lowercase-формат `aa:bb:cc:dd:ee:ff`.
6. Полностью одинаковые пары можно дедуплицировать.
7. Один активный MAC с разными IP или один активный IP с разными MAC —
   ошибка файла, а не частичный успех.
8. Непустая строка неправильной структуры или с некорректными обязательными
   полями делает выполнение неуспешным.

Время должно поступать через существующую абстракцию clock либо через
инъецируемую зависимость, чтобы тесты истечения аренды не зависели от
реальных часов.

## Успешный результат

Отправить в `POST /api/agent/v1/command_results`:

```json
{
  "results": [
    {
      "command_id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "ok": true,
      "error": null,
      "finished_at": "2026-10-13T14:00:03Z",
      "result": {
        "screens": [
          {
            "mac_address": "aa:bb:cc:dd:ee:ff",
            "ip_address": "192.168.1.10"
          }
        ]
      }
    }
  ]
}
```

`finished_at` — UTC RFC3339. Порядок `screens` не является частью контракта:
Hub самостоятельно сортирует новые экраны по IP. Успешный пустой массив
допустим и означает отсутствие активных аренд:

```json
"result": { "screens": [] }
```

Не отправлять `hostname`, lease expiry или client id: Hub их не хранит.

## Ошибки выполнения

При невозможности получить полный достоверный список отправить `ok: false`.
Поле `result` в ошибочном ответе не требуется.

Стабильные коды:

- `lease_file_missing` — файл отсутствует;
- `lease_file_unreadable` — файл существует, но открыть или полностью
  прочитать его невозможно;
- `invalid_lease_file` — нарушена структура, адреса некорректны или активные
  записи противоречат друг другу.

Пример:

```json
{
  "results": [
    {
      "command_id": "cmd_7b03539f-6ea8-4cf0-a719-1831b833f639",
      "ok": false,
      "error": "invalid_lease_file",
      "finished_at": "2026-10-13T14:00:03Z"
    }
  ]
}
```

Не включать путь файла, содержимое leases, токен или другие чувствительные
данные в отправляемое поле `error`.

## Доставка и идемпотентность

- Использовать существующий bearer token и HTTP-клиент агента.
- Команда считается доставленной Hub только после HTTP 200 от
  `command_results`.
- Сетевой сбой, timeout или HTTP 5xx оставляет результат для повторной
  отправки по существующей политике retry.
- HTTP 401 обрабатывается общей политикой отклонённого токена.
- HTTP 422 означает несовпадение контракта. Записать структурированную ошибку
  без секретов и не отмечать результат доставленным.
- Повторное исполнение или отправка одного `command_id` не должны создавать
  локальные побочные эффекты, кроме повторного чтения файла и повторной
  доставки результата.
- Не блокировать воспроизведение, загрузку медиа и отправку play events на
  время retry результата команды.

Если в репозитории уже есть durable queue результатов команд, расширить её
структуру полем `result`. Если такой очереди нет, применить существующий
механизм надёжной доставки команд; не создавать отдельный несовместимый
формат только для `fetch_screens`.

## Разбиение ответственности

Следовать текущим пакетам репозитория. Логические границы должны оставаться
отдельно тестируемыми:

- parser leases: bytes + current time → нормализованные пары либо typed error;
- handler `fetch_screens`: чтение файла и построение результата команды;
- Hub DTO/client: сериализация дополнительного `result`;
- orchestration: маршрутизация станционной команды и retry доставки.

Parser не должен обращаться к сети, Hub или ADB. HTTP-клиент не должен знать
формат dnsmasq.

## Обязательные тесты

Добавить unit/integration tests в принятом в репозитории стиле:

1. Одна валидная неистёкшая аренда возвращается в каноническом виде.
2. Несколько аренд возвращаются без зависимости от их порядка.
3. `expires = 0` считается активной арендой.
4. Истёкшая аренда исключается.
5. Пустой корректный файл даёт успешный пустой список.
6. Пустые строки игнорируются.
7. Некорректный timestamp, MAC, IPv4 или число полей даёт
   `invalid_lease_file`.
8. Конфликт MAC→несколько IP и IP→несколько MAC даёт
   `invalid_lease_file`.
9. Полный повтор пары дедуплицируется.
10. Отсутствующий файл даёт `lease_file_missing`.
11. Ошибка доступа/чтения даёт `lease_file_unreadable`.
12. Команда с `screen_id: null` маршрутизируется без экранных операций.
13. Успешный JSON точно соответствует контракту `result.screens`.
14. Ошибочный JSON не содержит частичного списка.
15. HTTP 200 завершает доставку; network error/5xx сохраняет результат для
    retry; 422 не помечает его доставленным.
16. Повторная доставка того же `command_id` безопасна.
17. Тесты не читают настоящий `/var/lib/misc/dnsmasq.leases`: путь или reader
    подменяется зависимостью.

Запустить полный штатный набор проверок репозитория станции. Для Go-проекта
минимум:

```bash
go test ./...
```

Также выполнить существующие formatter, linter и race checks, если они
настроены в репозитории.

## Документация и эксплуатация

Обновить README или операторскую документацию:

- процессу нужен read-доступ к `/var/lib/misc/dnsmasq.leases`;
- предпочтительно выдать доступ через ограниченную группу, не запускать весь
  агент от root только ради файла;
- описать коды ошибок `lease_file_*`;
- не рекомендовать менять права файла на world-readable;
- указать, что обнаружение запускается оператором на Hub.

Если systemd unit требует дополнительной группы, применить минимальное
изменение `SupplementaryGroups=` и документировать необходимую настройку
dnsmasq. Не ослаблять остальные sandbox/security параметры unit.

## Готово, когда

- агент принимает `fetch_screens` с `screen_id: null`;
- корректно читает и валидирует активные dnsmasq leases;
- отправляет согласованный успешный или ошибочный результат;
- повторяет недоставленный результат без влияния на эфир;
- все новые и существующие тесты, formatter и linter проходят;
- документация объясняет безопасный доступ к leases.
