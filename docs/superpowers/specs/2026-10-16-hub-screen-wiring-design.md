# Привязка экранов в config агента — дизайн для Broadcast Hub

> **Назначение:** нормативное описание доработки Hub, по которому новый агент
> реализует выдачу `adb_serial`, `mac` и `stream_port` в
> `GET /api/agent/v1/config`.
>
> **Репозиторий:** `mediateca-broadcast`. Station (`mediateca-station`) в этой
> задаче не менять.
>
> **Контекст:** файл развёртывания mini-PC содержит только IP станции и
> agent token. Какой телевизор какой поток слушает, решает Hub. Несколько
> экранов одной станции с одной и той же лентой эфира слушают один
> `stream_port`.

Связанные документы:

- `docs/superpowers/specs/2026-10-09-hub-agent-control-plane-api.md` — уже
  реализованный control plane. Этот документ его расширяет, не заменяет.
- `mediateca-broadcast/app/domain/agent/config_builder.rb` — текущий сборщик
  config. Экраны сейчас: `id`, `name`, `orientation`.
- `mediateca-broadcast/app/domain/agent/screens/synchronize.rb` — discovery
  уже пишет `mac_address`, `ip_address`, `network_registered`.

---

## 1. Что меняется

`GET /api/agent/v1/config` для каждого экрана станции дополнительно сообщает
станции, куда подключаться и какой порт Voxel `broadcast` слушать.

Носитель — config, не пакет v2. Пакет остаётся расписанием со своим ETag.
Привязка телевизора не должна инвалидировать пакет и не должна скачивать
медиа заново.

Текущий бинарник station неизвестные поля JSON игнорирует и по-прежнему берёт
serial и порт из локального YAML. Поэтому каждый экран станции остаётся в
массиве `screens` с прежними `id`, `name`, `orientation`. Поля привязки
добавляются рядом. Экран без привязки эти поля не получает, но из массива
не пропадает: иначе текущая станция пометит его `not_in_hub_config` и
замолчит.

Пакет v2, `play_events`, telemetry, commands и `fetch_screens` не меняются.
`screen_ids` в записях пакета остаются поэкранными: общий порт не сливает
доказательства проигрывания.

## 2. Тело экрана

### 200, экран с привязкой

```json
{
  "station_id": 3,
  "offline_cache_hours": 24,
  "screens": [
    {
      "id": 7,
      "name": "Entrance",
      "orientation": "landscape",
      "adb_serial": "192.168.33.182:5555",
      "mac": "78:53:33:4b:2c:29",
      "stream_port": 8091
    },
    {
      "id": 8,
      "name": "Hall",
      "orientation": "landscape",
      "adb_serial": "192.168.33.183:5555",
      "mac": "78:53:33:4b:2c:30",
      "stream_port": 8091
    }
  ]
}
```

Экраны 7 и 8 делят `8091`, потому что их лента эфира совпала.

### 200, экран ещё без сети

```json
{
  "id": 9,
  "name": "Window",
  "orientation": "portrait"
}
```

Ключей `adb_serial`, `mac`, `stream_port` нет. Не слать `null` и не слать
пустую строку: будущая станция отличает «поля нет» от нулевого порта.

| Поле | Тип | Когда есть |
| --- | --- | --- |
| `id`, `name`, `orientation` | как сейчас | всегда |
| `adb_serial` | string `host:5555` | экран в сети и есть IPv4 |
| `mac` | string | вместе с `adb_serial`, если у экрана есть MAC |
| `stream_port` | int | есть привязка и у ленты назначен канал |

`adb_serial` — адрес ADB. Порт всегда `5555`. Отдельной колонки под него нет.

`mac` — нижний регистр, шесть октетов через двоеточие (`aa:bb:cc:dd:ee:ff`).
Будущая станция передаёт его в Wake-on-LAN. Без MAC станция будит телевизор
только по ADB, это уже её поведение.

`stream_port` — один канал Voxel на mini-PC: один процесс `broadcast`, один
feeder, несколько телевизоров открывают `http://192.168.33.1:<port>/`.
Повторение порта у нескольких экранов — штатный случай, не ошибка валидации.

`tv_monitor` не меняется. Правило «пустой объект выключает авторестарт»
из control-plane спеки остаётся.

## 3. Кого привязывать

Привязка есть у экрана, у которого одновременно:

- `network_registered = true`;
- `ip_address` — IPv4-хост.

Иначе поля привязки опускаются. Устаревший IP у экрана, который discovery
снял с регистрации, в config не попадает.

`adb_serial` собирается из IP без маски CIDR. Значение `inet` в PostgreSQL
может выглядеть как `192.168.33.182/32`; в JSON уходит `192.168.33.182:5555`.

`mac` берётся из `screens.mac_address`. Если MAC пуст, ключ `mac`
опускается. `adb_serial` от MAC не зависит. `stream_port` зависит только
от канала (§4–§5): у экрана в сети с пустой лентой есть `adb_serial` и нет
`stream_port`.

---

## 4. Один плейлист — один порт

Лента экрана — упорядоченный список слотов горизонта
`Playlists::EnqueueRegen.horizon_dates(station)` по плейлистам
`station.playlists.current`.

Слот:

| Поле | Откуда |
| --- | --- |
| `for_date` | дата плейлиста, ISO `YYYY-MM-DD` |
| `offset_seconds` | `playlist_items.offset_seconds` |
| `starts_at` | `broadcast_day_starts_at + offset`, ISO8601, либо `null`, если якоря нет |
| `duration_seconds` | длительность пункта |
| `media_id` | `media_asset_id` |

В слот попадает пункт, у которого этот экран есть в `playlist_item_screens`
и у медиа есть вложение, которым пакет и так отдаёт эфир
(`broadcast_delivery_attachment`). Пункт без такого вложения в ленту не
входит — его нет и в пакете.

Порядок слотов: `for_date`, `offset_seconds`, `media_id`.

Дайджест ленты — SHA256 канонического JSON этого массива. В дайджест не
входят `screen_ids`, подписанный URL блоба, `source_kind`, `media_plan_id`.
Совпадает то, что телевизор увидит во времени: тот же ролик в ту же точку
ленты. Два экрана с равным непустым дайджестом слушают один порт.

Пустая лента порт не получает. Молчащий экран не поднимает `broadcast`.

Горизонт неполный, если хотя бы на одну дату из
`horizon_dates` нет плейлиста `current`. Тогда config **не** создаёт новые
каналы и **не** удаляет уже сохранённые. Экраны, у которых канал уже был,
продолжают получать свой `stream_port`. `adb_serial` и `mac` при неполном
горизонте всё равно отдаются: они зависят от сети экрана, не от ленты.
Иначе poll посреди `GenerateForDateJob` переназначает порты и телевизоры
переподключаются.

Сбор config не ставит `GenerateForDateJob`. Это остаётся работе пакета
(`Playlists::PackageFromPlaylists`) и кнопке пересборки в админке.
`ConfigBuilder` не вызывает `PackageFromPlaylists`: у того метода есть
побочный эффект постановки regen, а admin show вызывает оба сборщика.

## 5. Реестр каналов

Порт принадлежит дайджесту ленты, не строке `screens`. Колонки
`stream_port` на `screens` нет.

Таблица `station_stream_channels`:

| Колонка | Ограничение |
| --- | --- |
| `station_id` | FK на `stations`, `ON DELETE CASCADE`, not null |
| `timeline_digest` | string, not null |
| `stream_port` | integer, not null |
| уникальность | `(station_id, timeline_digest)` и `(station_id, stream_port)` |

Пул портов станции: **8091..8190** включительно. Hub — единственный
назначающий. Эти порты слушает Voxel на адресе телевизионной сети
mini-PC (`192.168.33.1`), не Hub.

Пересчёт при полном горизонте, под `station.with_lock`:

1. Посчитать дайджест каждого привязываемого экрана.
2. Сгруппировать непустые дайджесты.
3. Дайджест, у которого строка уже есть, сохраняет порт.
4. Новый дайджест получает наименьший свободный порт пула.
5. Строки дайджестов, которых больше нет ни у одного привязанного экрана,
   удаляются, порт возвращается в пул.
6. Если пул исчерпан, новые дайджесты остаются без строки. Их экраны
   уходят в config без `stream_port`. Ответ config всё равно **200**.
   Уже выданные порты не отбираются, чтобы освободить место.

Повторный poll с тем же набором лент возвращает те же порты. Экран,
чья лента совпала с уже существующим дайджестом, получает порт этого
дайджеста, а не новый.

Запись реестра происходит внутри сборки config. Её вызывают и agent poll,
и превью на `Admin::StationsController#show`. Повторный вызов с теми же
данными ничего не меняет.

## 6. Что не делать

- Не менять shape `GET /api/agent/v2/package` и его ETag.
- Не выкидывать экран из `screens` из-за отсутствия IP, MAC или порта.
- Не назначать порт вручную из админки и не добавлять форму порта.
- Не менять `fetch_screens` и `Agent::Screens::Synchronize`. Discovery уже
  заполняет MAC и IP.
- Не менять репозиторий `mediateca-station`. Потребление новых полей —
  отдельная задача станции: локальный YAML сможет стартовать без экранов,
  а feeder будет один на порт. Пока станция этого не умеет, повторяющийся
  `stream_port` для неё безвреден: она его не читает.
- Не слать в config адрес Hub, токен или путь к бинарнику `broadcast`.
  Это по-прежнему локальный YAML mini-PC.

## 7. Проверка

Расширить `spec/domain/agent/config_builder_spec.rb` и
`spec/requests/api/agent/v1/configs_spec.rb`.

Обязательные случаи:

1. Экран с `network_registered`, IPv4 и MAC получает `adb_serial` без
   `/32`, `mac` в каноническом виде и `stream_port` из пула, если лента
   непустая и горизонт полный.
2. Два экрана с одними и теми же слотами получают один `stream_port`.
3. Два экрана с разным `media_id` или разным `offset_seconds` получают
   разные порты.
4. Экран без IP или с `network_registered: false` остаётся в массиве
   только с `id`, `name`, `orientation`.
5. Второй вызов `ConfigBuilder` возвращает тот же порт.
6. Третий экран с уже известной лентой получает порт этой ленты.
7. Неполный горизонт не создаёт новый канал и не удаляет существующий.
8. Пустая лента не создаёт канал.
9. Сборка config не ставит `GenerateForDateJob`.
10. Ответ v2 package в существующем request-спеке не приобретает
    `adb_serial` и `stream_port`.

Превью на странице станции отдельно не верстать: `@agent_config` уже
печатает результат `ConfigBuilder`.
